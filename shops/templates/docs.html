Good questions

{{ icon('bill') }} What is the bill?

When the AI asks without paying, we don't say "no". We say "this costs 1¢" and include everything needed to pay: the price, the currency, our wallet, and a time limit of 60 seconds.

This uses a rarely used part of the web called "402 Payment Required", which was reserved for exactly this, decades ago.

{{ icon('sign') }} What does "signing" mean?

Think of signing a cheque. The signature:

  • proves who approved the payment,
  • fixes exactly how much and to whom,
  • and can't be changed afterwards. Change one digit and the signature no longer fits.

The AI's wallet signs with a secret key that never leaves the wallet. We never see it.

{{ icon('shield') }} Why can't someone cheat?

Before we hand over any data, {{ brand }} checks the signed payment slip against the bill:

  • Amount: the slip must pay the full price. Paying less is refused.
  • Receiver: the money must go to our wallet, not someone else's.
  • Expiry: a slip is only valid for 60 seconds.
  • Used once: every slip has a unique number, so the same slip can't pay twice.

We check amount and receiver ourselves, first. The payment checker and the blockchain then enforce expiry and one-time use. You can try cheating in the box below: it gets refused.

{{ icon('coin') }} What is USDC?

USDC is a digital dollar: 1 USDC is always worth $1. It lives on a blockchain, so a program can pay with it in seconds, even for tiny amounts like 1¢, which a card payment can't do.

{{ icon('lab') }} What is MOCK MODE?

In mock mode, payments are simulated until our local blockchain is connected. Everything else is real: the bills, the checks on amount and receiver, the refusals and the live dashboard.

No real money moves, receipts start with "0xmock" so they can't be mistaken for real ones, and expiry and one-time use are only enforced once the real payment checker is on.

For developers

Show technical details

{{ brand }} uses the x402 v2 protocol on Base Sepolia (testnet, eip155:84532). Payment data travels in three HTTP headers, each JSON encoded as base64:

  • {{ h_required }}: the bill, sent with HTTP 402.
  • {{ h_signature }}: the signed EIP-3009 transferWithAuthorization, sent by the buyer on the retry.
  • {{ h_response }}: the receipt, sent with HTTP 200.

A refused payment gets 402 again, with the reason in error (e.g. amount_too_low, authorization_wrong_recipient).
